# 0.2.0rc1 产品复盘与下一步建议

日期：2026-08-31。本文基于当前代码、接口、启动流程、独立回归结果和本机
Qwen 运行验证撰写。它是候选版本的改进清单，不把尚未测得的数据描述成结论。

## 当前产品判断

D-VOICE 已经有一个清楚且有价值的核心：**只有登记的本人能在本地唤醒后，
通过语音调度本地 AI 和已明确配置的 agent**。这个价值比“又一个语音聊天框”
更具体，也更容易建立信任。

当前最合适的定位是“本机 AI 工作流的安全语音入口和进度管家”，而不是
“完全自主的通用智能管家”。前者与声纹、唤醒、任务叙述和本地 Qwen 的能力吻合；
后者会让用户期待全天候可靠对话、活体防护、复杂家庭多用户和无感全双工，
这些还没有通过验收。

## 技术建议

| 优先级 | 建议 | 原因 | 可验收结果 |
| --- | --- | --- | --- |
| P0 | 建立真实声纹与重放测试集，并用 `vocalis calibrate` 按人、距离、噪声记录 FAR/FRR/EER | 当前声纹阈值尚无真实数据支撑；录音和声音克隆仍是已知风险 | 每位测试者至少 20 次本人/陌生人/回放样本，给出阈值、FAR、FRR、拒绝原因和复测日期 |
| P0 | 加入活体挑战与危险操作的显式二次确认 | 唤醒词和声纹不足以授权删除、支付或外部发布 | 高风险 connector 必须显示确认卡片/本地快捷键；语音只能提出请求，不能批准 |
| P0 | 进行 8 小时常驻压力测试 | 长时间音频队列、模型、设备恢复才是“持续在线”的真正风险 | 记录 CPU、内存、队列长度、模型状态、设备异常和恢复时间；无音频持久化 |
| P1 | 将音频设备选择、采样率、模型预热和依赖诊断做成 `vocalis doctor` | 目前首次失败信息分散在依赖、缓存、SAPI、麦克风和模型服务之间 | 一条命令报告每项 Ready/Blocked、可复制修复命令与隐私影响 |
| P1 | 为语音会话引入每用户隔离的短期对话历史并在休眠时清空/摘要 | 当前会话状态已锁定说话人；多用户前必须连同上下文隔离 | 切换用户后不能读取前一用户语音上下文；有自动化回归 |
| P1 | 把本地 TTS 作为正式受支持后端并完善错误恢复 | 当前 SAPI 实机发声尚未完成验证，Edge-TTS 会联网 | 本地语音有设备自检、失败时文字可用、明确不回退到网络 |
| P2 | 安全恢复全双工 | 当前半双工牺牲体验是正确取舍，但下一阶段可用回声消除、说话人确认和“只中断不执行”策略逐步恢复 | 播报可打断；中断后的新命令仍需声纹和会话验证，且有回声攻击测试 |
| P2 | 为 Qwen 增加延迟、首次 token、规则降级比率、模型不匹配遥测（仅本机可查看） | 当前已有健康检查和回复来源，缺乏体验质量证据 | HUD 能显示本次来源、延迟、降级原因；不上传文本、声纹或录音 |

## 产品与交互建议

| 优先级 | 建议 | 用户得到的变化 |
| --- | --- | --- |
| P0 | 首次启动改为四步引导：检查模型 → 选麦克风 → 录声纹 → 练习“唤醒、确认、指令、休眠” | 用户理解两句交互的原因，不会把唤醒句当作被忽略 |
| P0 | 在 HUD 把状态固定为三个大字：已关闭麦克风 / 本地待机 / 已由某用户唤醒 | 用户一眼知道系统是否收音、是否会调用模型，而不必猜绿色圆点含义 |
| P1 | 给出“低风险语音动作”白名单与“需屏幕确认动作”列表 | 任务分发、状态查询和回答可自然语音化；外发、删除、密钥、付款等需要明确确认 |
| P1 | 增加命令回执卡片：识别文本、验证结果、将要调用的 agent、是否本地 Qwen、可取消按钮 | 让用户在错误识别或误唤醒时有可见的纠正点 |
| P1 | 提供三种可选模式：专注（默认安全半双工）、演示（更积极播报）、隐私（关屏幕监管、关网络 TTS、只文字/本地语音） | 把隐私与响应速度的取舍变成可理解的选择 |
| P2 | 增加适合中文的唤醒短语自定义向导 | 当前短语可配置，但用户不知道怎样避免与日常词混淆 |

## 用户与信任建议

1. 把“休眠零 token”始终写成“零**大模型**调用”，并在界面显示本地 ASR/声纹仍在工作。准确表述比营销更容易建立信任。
2. 首次登记前展示一页生物特征说明：存储位置、删除入口、重登记后旧向量如何处理、录音是否保存。默认不保存原始音频。
3. 明确区分“本地 Qwen”与“完全离线”。如果使用 Edge-TTS、外部 CLI agent、MCP 或屏幕监控，界面要显示对应的数据流和开关。
4. 对失败使用可行动文案。例如“未识别为已登记声音；未把内容发送给 Qwen”优于笼统的“失败”。同时不要显示完整拒绝转写，避免旁人说话出现在屏幕。
5. 为旁观者提供可见的收音指示和一键硬停止。关闭网页不等于停止服务的行为必须持续提示。

## 发布建议

在完成下列条件前，应维持 `0.2.0rc1`，不要称为 1.0 或生产版：

- 本人、陌生人、回放、噪声和距离的测试数据足够支持阈值；
- 本地 SAPI 或正式选定的离线 TTS 已完成真实设备验收；
- 连续运行、设备断连/重连、系统休眠恢复和 Qwen 重启均可恢复且有证据；
- 高风险工具有独立确认；
- 首次安装诊断能让非开发用户独立完成声纹登记与本地模型检查。

完成这些条件后，0.2.0 可以作为“本地、安全、半双工语音工作流管家”发布；
然后再把全双工、多用户和活体认证排入后续版本。
